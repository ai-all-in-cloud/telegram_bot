## 📌 一、 提案背景與解決痛點

在過往的運作模式中，當主機重開機、反重力 IDE 視窗被意外關閉、或本機 Python 程序中斷時，AI 員工常面臨以下痛點：
1. **重開機後斷線**：必須由工程師手動進終端機重新敲指令啟動 Listener 與反重力。
2. **誤觸關閉失聯**：反重力或監聽程式被關掉後無人知曉，主管在 Telegram 指派任務時無人響應。
3. **新進 AI 員工設定繁複**：每新增一位 AI 員工，環境與背景排程需要重寫一次。

為此，001 柚木已實作出一套**「萬無一失的雙核心守護神系統」**，實現：
* ✅ **重開機 100% 自動開機自啟**（反重力大腦 + Telegram 監聽雙雙就位）。
* ✅ **定時巡檢防關閉（每 5 秒心跳）**：無論誰誤關反重力或監聽進程，系統自動拉起復原。
* ✅ **全體新員工一鍵通用範本化**：日後 002、003 AI 員工到職只需執行一行安裝指令即可就緒！

## 🛡️ 二、 萬無一失守護技術架構

```mermaid
flowchart TD
    subgraph 開機 / 登入觸發層 (雙保險)
        L1["Windows 工作排程器 (Task Scheduler)<br/>LogonTrigger + RestartOnFailure x 999"]
        L2["Windows Startup 啟動資料夾<br/>Start-AllInCloudGuardian_XXX.vbs (完全靜音)"]
    end

    subgraph 核心守護引擎 (Daemon)
        G["all_in_cloud_guardian.ps1<br/>(獨立常駐背景，單實例互斥鎖)"]
    end

    subgraph 守護標的 (每 5 秒心跳巡檢)
        T1["反重力大腦視窗<br/>(Antigravity.exe)"]
        T2["Telegram 雙向監聽核心<br/>(bot_listener.py)"]
    end

    L1 --> G
    L2 --> G
    G -->|巡檢 1: 若離線即自動啟動| T1
    G -->|巡檢 2: 若斷線即自動喚醒| T2
    T2 -->|Telegram 接收指令| T1
```

### 關鍵機制特點：
1. **雙層開機啟動防護**：Windows 工作排程器（系統級事件）搭配 Startup 資料夾（使用者級事件），即使其中一項受群組原則限制，另一項亦能 100% 確保開機自啟。
2. **完全靜音 (Zero-Window-Flash)**：全鏈路採用 `wscript.exe` 封裝，開機與喚醒時螢幕上**絕不出現任何 CMD/PowerShell 黑色視窗快閃**，體驗極致絲滑。
3. **防崩潰心跳巡檢 (Self-Healing Watchdog)**：每 5 秒偵測一次進程狀態，實測強制殺死進程後，守護引擎在 **7 秒內自動偵測並重新拉起**。
4. **單實例防衝突 (Mutual Exclusion)**：內建 PID 偵測，重複啟動時主動識別並退出，徹底根絕 Telegram API `409 Conflict` 錯誤。

## 🚀 三、 未來新進 AI 員工 (002、003...) 一鍵到職部署標準流程

日後若有新 AI 員工（例如 002 號專項員工）入職，負責的主管或部署人員只需在該員工電腦執行以下標準指令：

### 步驟 1：建立該員工專屬啟動器 `start_listener.ps1`
將該員工的 `start_listener.ps1` 存放於其 G 槽資料夾（如 `G:\...\{AgentId}\start_listener.ps1`）。

### 步驟 2：執行一鍵守護安裝精靈
開啟 PowerShell 執行共用的安裝腳本：
```powershell
# 範例：002 號新員工入職
.\setup_guardian.ps1 -AgentId "002" -AgentName "員工代號"
```

### 步驟 3：全自動完成驗證
安裝腳本將自動：
1. 註冊專屬工作排程器（`歐印雲_002[代號]_Guardian`）
2. 佈署開機啟動資料夾 VBS
3. 立即拉起守護程序與監聽核心，並輸出健檢報告確認狀態皆為 🟢 正常運行！
